Резервная тема: «Ограничение влияния согласованных профилей в рекомендательных системах при сохранении рекомендаций для нишевых пользователей»

**Статус.** Содержательная альтернатива, но не равноправная готовая рекомендация на 13 ноября. Доступность исходных данных и опубликованных результатов подтверждена; точный рецепт воспроизведения выбранной таблицы ещё не установлен. До закрытия этого вопроса предпочтительны темы A и B.

**Вопрос.** Позволяет ли ограничение избыточного вклада похожих профилей уменьшить продвижение целевого объекта без ухудшения рекомендаций для добросовестных пользователей с узкими интересами?

**Основа.** RecAD (RecSys 2023) предоставляет обработанные данные, модели рекомендаций и атак. Загружен архив MovieLens и проверены реальные train/valid/test-файлы. Таблица 2 содержит результаты атак по target HR@k. Например, для ML-1M при HR@10 указаны 0,0050 без атаки, 0,0071 для AUSH и 0,0094 для Legup. Это ориентиры существующей работы, а не результаты стартера; текущие параметры репозитория не гарантируют их воспроизведения.

**План.** Один рекомендатель, несколько стандартных атак и одна адаптивная атака с разнообразными профилями. Сравнить отсутствие защиты, простое ограничение веса, PCASelectUser и предлагаемый метод. Оценивать изменение target HR@k одновременно с качеством обычных рекомендаций и потерями на нишевых пользователях. Не использовать метки внедрённых профилей в признаках защиты. Trust-GRS (AAAI 2025) — обязательная современная работа для сравнения постановок; её просмотренный репозиторий содержит отдельные модули, но не подтверждён как законченный исполняемый baseline.

**Условия включения в основной выбор.** Установить victim model, целевые объекты, attacker budget, видимость данных, seed и preprocessing для одной опубликованной строки; проверить метрики официальным workflow; явно переопределить validation path. В просмотренной версии RecAD конфигурация explicit-data направляет `path_valid` на test-файл. Это обнаруженная особенность текущего кода, а не обвинение опубликованного эксперимента в утечке. Для новых экспериментов test не используется при выборе параметров.

**Подготовлено.** Проверены опубликованная статья и исходный код, зафиксированы ревизии и контрольные суммы, написан аудит обработанных данных и тест корректного знаменателя target HR. Обучение моделей и воспроизведение таблицы не выполнены. Резерв можно довести до готового предложения, если быстро удастся восстановить точный протокол; иначе тема не выбирается только на основании общей популярности MovieLens.
